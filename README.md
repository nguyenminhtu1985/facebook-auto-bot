# Facebook Auto Bot

Pick a topic — or let it pick one — and it writes a Facebook Page post, generates a
matching image, and publishes it. On autopilot it does all of that on a schedule with
nobody clicking anything.

Every generation source is free. No paid API keys anywhere in the pipeline.

## What it does

- **Your own topics.** Paste a list of subjects or keywords for your niche and autopilot
  works through it, least recently used first, so everything is covered before anything
  repeats. Google Trends and a curated evergreen list fill in while the list is empty,
  or alongside it if you choose.
- **Copy** written for the Facebook feed: a scroll-stopping hook, a short body, and a
  question that invites comments, plus 3–5 hashtags.
- **Images** generated by AI or pulled from free stock, always re-hosted on your own
  storage so a post's image keeps working even if the free provider goes away.
- **Instagram too.** An Instagram professional account linked to your Page is published to
  with the same image and caption; each post goes to whichever destinations you switch on.
- **Your own AI keys.** A Providers screen lists every service the app can use — Groq,
  Gemini, Claude, ChatGPT, Pollinations, Pexels — with what each costs, which are active,
  and a Test button. Paste your own keys, pick the model, set the order.
- **Queue** for drafts and scheduled posts, with a history of what actually published.
- **Autopilot** that invents a topic, writes, and publishes on its own, bounded by
  posts-per-day, allowed posting hours, and your timezone.

## Why Facebook and not Pinterest

Pinterest's API cannot deliver this. An App ID and Secret only buy Trial access, and
every Pin created with Trial access is a sandbox entity **visible only to its creator**.
Real public Pins need Standard access — a review that includes a video demo of your
OAuth flow.

Meta gets you further. Every app is automatically approved for
[Standard Access](https://developers.facebook.com/docs/graph-api/overview/access-levels/),
which covers acting on Pages belonging to people who have a role on the app — so you can
build, connect and publish to your own Page immediately, with no review.

There is still a catch, and it is worth knowing before you start: while your Meta app is
in **Development mode**, posts it creates
[are visible only to people with a role on the app](https://developers.facebook.com/docs/development/build-and-test/app-modes).
They are real Page posts, and they become visible to everyone the moment you switch the
app to **Live** — including the ones published earlier — but switching to Live requires
App Review for `pages_manage_posts`.

So: everything works end to end today, privately. Public reach is one review away, and
by the time you apply you already have the working integration reviewers ask to see.

Note that Meta removed personal-profile publishing in 2018. This posts to **Pages**.

## Deploy your own

**[Full installation guide →](INSTALL.md)** — written for people who do not write code: every screen, every value, and the Meta settings that trip everyone up. About 30 minutes.

The short version. You need three free accounts: Vercel, Supabase, and a Meta developer account.

**1. Supabase** — create a project, open the SQL editor, and run
[`supabase/schema.sql`](supabase/schema.sql). From Project Settings → API, copy the
Project URL and the `service_role` key.

**2. Deploy to Vercel** — import this repository and set four environment variables:

| Variable | What it is |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Your Supabase project URL |
| `SUPABASE_SERVICE_ROLE_KEY` | The `service_role` key (server-side only, never exposed) |
| `ADMIN_PASSWORD` | The password that opens your dashboard |
| `SESSION_SECRET` | Any long random string — `openssl rand -base64 32` |

Everything else is optional. See [`.env.example`](.env.example).

**3. Meta app** — create one at
[developers.facebook.com/apps](https://developers.facebook.com/apps) with the
**"Manage everything on your Page"** use case (*not* the Facebook Login one — Meta
treats them as incompatible). Add `pages_manage_posts` and `pages_read_engagement`,
create a login configuration, then open your deployment and go to
**Settings → Meta app**. Paste the App ID, App Secret and configuration ID there — no
redeploy needed — and copy the redirect URI shown on that screen into your Meta app's
**Valid OAuth Redirect URIs**.

Then hit **Connect**, pick a Page, and you are running.

### AI providers

Open **AI providers** in the dashboard to see every service the app can use, what it
costs, and which ones are active. Paste a key there and it works immediately — no
redeploy, no environment variable.

| Provider | Writes posts | Cost |
| --- | --- | --- |
| [Groq](https://console.groq.com/keys) | yes | Free tier — the recommended first key |
| [Google Gemini](https://aistudio.google.com/apikey) | yes | Free tier |
| [Claude](https://console.anthropic.com/settings/keys) | yes | Paid |
| [ChatGPT / OpenAI](https://platform.openai.com/api-keys) | yes | Paid |
| Pollinations | yes | Free, no key — but now turns away anonymous callers |
| Pollinations images | pictures | Free, no key |
| [Pexels](https://www.pexels.com/api/) | stock photos | Free tier |

They are tried in the order shown on that screen until one answers, so a paid provider
can sit behind a free one as a backstop. With none of them reachable the app falls back
to a plain template and says so on screen rather than passing it off as AI writing.

`GROQ_API_KEY`, `GEMINI_API_KEY` and `PEXELS_API_KEY` still work as environment
variables; a key saved on the screen takes precedence.

### Posting more than once a day

`vercel.json` schedules one daily run, because Vercel's Hobby plan rejects anything more
frequent — and it rejects it *after* the build succeeds, which surfaces as a deployment
that builds fine and then fails with no error text. Every autopilot guard is idempotent,
so to fire the other posting slots, point a free external cron (cron-job.org,
UptimeRobot) at `/api/cron/process-queue` and set `CRON_SECRET` so only your scheduler
can trigger it.

## Security notes

- The dashboard and the entire API are behind a single admin session cookie
  (HMAC-signed, `ADMIN_PASSWORD`). The cron route accepts `CRON_SECRET` instead, and
  falls back to requiring the session when no secret is configured.
- The Meta App Secret, the long-lived user token, and Page access tokens are stored in
  your own Supabase database and are stripped from every API response — the browser only
  ever learns *whether* they are set.
- Page tokens are fetched server-side when you choose a Page, so a publishing credential
  never travels through the browser.

## Local development

```bash
npm install
cp .env.example .env.local   # fill in Supabase + admin values
npm run dev
```

## Stack

Next.js 16 (App Router) · TypeScript · Tailwind v4 · Supabase (Postgres + Storage) ·
Meta Graph API v26.0 · Groq / Gemini / Pollinations for text · Pollinations / Pexels for
images.
